# SchoolOS — Reverse Engineering / Competitor Research

## Purpose

Study mature ERP products to discover workflows, UX, edge cases, module relationships, and expected behavior.

The goal is independent implementation, not copying proprietary software.

## Authorized scope

Only analyze:

- apps we have permission to analyze
- public demos
- legitimately obtained APKs/test builds
- public documentation

Never:

- bypass authentication
- access private customer data
- obtain or use private credentials
- defeat access controls
- copy source code/assets/branding
- use exposed secrets

## Android research

The Android reverse-engineering skill may be used for authorized APK analysis.

Potential observations:

- framework
- package structure
- API clients
- request patterns
- screen/network relationships
- configuration
- obfuscation

Treat extracted information as research evidence.

## Research outputs

For each competitor record:

- product
- version/date
- platform
- authorization basis
- role
- module
- screen
- workflow
- fields
- validation
- notifications
- permissions
- reports
- edge cases
- evidence
- confidence
- SchoolOS implication

## Rule

Competitor behavior becomes a requirement only after analysis and product decision.

Do not paste extracted proprietary source code into SchoolOS.
